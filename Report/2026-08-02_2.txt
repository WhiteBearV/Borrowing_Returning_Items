## สิ่งที่ทำสำเร็จวันนี้ ✅

### การตัดสินใจเชิงสถาปัตยกรรม: ยิง API ผ่าน `/api` origin เดียว

พบว่า `frontend/vite.config.js:8-13` **มี proxy `/api` → `localhost:8000` พร้อม rewrite อยู่แล้ว**
แต่ frontend ไม่ได้ใช้เพราะ `VITE_API_URL` ตั้งเป็น URL เต็ม (`http://192.168.1.164:8000`)

แค่ตั้ง `VITE_API_URL=/api` แล้วให้ nginx rewrite แบบเดียวกับ vite → ได้ 5 อย่าง
**โดยไม่แก้โค้ด frontend สักบรรทัด**: ไม่ต้องตั้ง CORS / IP ไม่ถูกฝังใน bundle /
ไม่ต้องเปิด port 8000 / วาง rate limit + จำกัดขนาดไฟล์ที่ nginx ได้ / เติม TLS ทีหลังแก้ไฟล์เดียว

ตรวจแล้วใช้ได้จริงทุกจุด: `axiosInstance.js:4` baseURL, refresh interceptor `:26`
(ใช้ `api.defaults.baseURL` จึงตามไปด้วย) และ `imgSrc` ทั้ง 5 จุดที่ประกอบ URL รูป

**ข้อควรระวังที่บันทึกไว้:** ห้าม proxy ตาม path prefix ตรง ๆ แทน `/api` เพราะ route ฝั่ง React
มี `/dashboard` (`App.jsx:45`) และ `/equipment` (`:50-51`) ซึ่งชนกับ API prefix พอดี

## บทเรียนสำคัญ: เทสต์ concurrency ตัวแรกใช้ไม่ได้ 🔴

เทสต์ race condition เวอร์ชันแรกยิง `approve_request` 2 ใบพร้อมกันด้วย `asyncio.gather`
แล้ว assert ว่าต้องผ่านใบเดียว — **มันผ่าน**

แต่พอลอง**ถอด `with_for_update()` ออกแล้วรันซ้ำ มันก็ยังผ่านอยู่ดี** แปลว่าเทสต์ไม่ได้ทดสอบอะไรเลย
สาเหตุคือผลลัพธ์ขึ้นกับจังหวะ scheduler ของ asyncio ล้วน ๆ ไม่ได้เกิดการชนจริง

เขียนใหม่ให้บังคับชนแน่นอน: ให้อีก transaction ถือ row lock พร้อมหักสต็อกจนหมดค้างไว้
แล้วค่อยปล่อย — ถ้า `approve_request` ไม่ล็อกแถวจะอ่านได้ค่าเก่าแล้วอนุมัติสำเร็จทั้งที่ของหมด
ยืนยันแล้วว่า **ถอด fix ออก → เทสต์พัง / ใส่กลับ → ผ่าน**

**บทเรียน:** เทสต์ concurrency ทุกตัวต้องพิสูจน์ว่าถอด fix ออกแล้วมันพังจริง ไม่งั้นได้เทสต์ปลอม

| backend ต่อ DB ไม่ได้บน prod | prod ไม่ override `DATABASE_URL` จึงใช้ค่า dev ที่ชี้ `localhost` | แก้แล้ว — ตั้งใน `environment:` ของ compose |
| แอป crash loop ถ้ายังไม่ตั้ง SMTP | `MAIL_FROM` fallback `dev@localhost` ไม่ผ่าน validator pydantic | แก้แล้ว — เจอตอนยกสแตกจริงเท่านั้น |
| ไฟล์ทะเบียนครุภัณฑ์ 93 ไฟล์โหลดได้โดยไม่ต้อง login | เขียนลง `UPLOAD_DIR` ที่ mount เป็น StaticFiles สาธารณะ | แก้แล้ว — ย้ายไป `import_tmp/` นอก `UPLOAD_DIR` |
| **SMTP ยังไม่ยืนยันว่าใช้ได้** | ยังไม่ได้ตัดสินใจเรื่อง Gmail App Password (ค้างจากรอบแรก) | ต้องทดสอบส่งจริงบน VM ก่อน แล้วค่อยตัดสินว่าจะตั้ง `DEV_AUTO_VERIFY_EMAIL` เป็นอะไร |
| ยังไม่ได้ทดสอบ E2E บนเบราว์เซอร์จริงหลังรื้อ deploy | ทดสอบด้วย curl ผ่าน nginx เท่านั้น | ทำบน VM หลัง deploy |
| ยังไม่ได้ซ้อม backup/restore จริง | สแตกทดสอบถูกรื้อไปแล้ว | ต้องซ้อม 1 รอบบน VM — backup ที่ไม่เคย restore ไม่นับว่ามี |

## แผนวันพรุ่งนี้ 📋

1. [ ] **Deploy ขึ้น Proxmox VM จริง** — `cp .env.prod.example .env` แล้วแก้ `SECRET_KEY`,
       `POSTGRES_PASSWORD`, `FRONTEND_URL`/`APP_BASE_URL` เป็น IP ของ VM (คำสั่งครบใน `DEPLOY-PLAN.md`)
2. [ ] **ทดสอบ SMTP จริง** — สมัคร 1 ใบ ดูว่าอีเมล verify เข้ากล่องจริงไม่ใช่แค่ออก log
       → ผลตัดสินว่าจะปิด `DEV_AUTO_VERIFY_EMAIL` ได้ไหม
3. [ ] **สร้าง admin คนแรกบน VM** ด้วย `scripts/create_admin.py`
4. [ ] **E2E บนเบราว์เซอร์** — ยื่นคำขอ → อนุมัติ (สต็อกลด) → ต่อเวลา → รับคืน durable `ok` (สต็อกคืน)
       + วัสดุ `used_up` (สต็อกไม่คืน) → `completed` → โหลด PDF → เช็ค audit log
5. [ ] **ซ้อม backup/restore 1 รอบ** — `tar tzf` ต้องเห็นไฟล์รูปจริง แล้ว restore กลับมา login ได้
6. [ ] **ตั้ง cron backup ตี 2** บน VM
7. [ ] ทดสอบ scheduler: ตั้ง `due_date` ย้อนหลัง เรียก `_check_overdue()` มือ
       → ต้องแจ้งครั้งเดียวไม่ซ้ำ และคนที่ต่อเวลาแล้วต้องไม่ถูกทวง
8. [ ] ต่อปุ่ม remind แบบ manual เข้า UI (ค้างจากรอบแรก)

## สถานะโดยรวม

**Backend:** ~98% — ฟีเจอร์ครบ + ปิดช่องโหว่ race condition/upload/rate limit แล้ว
เหลือแค่ยืนยัน SMTP บนเครื่องจริง

**Frontend:** ~97% — ครบ flow หลัก + แก้ตารางแอดมินให้เลื่อนบนมือถือได้
เหลือ E2E บนเบราว์เซอร์จริงหลังรื้อ deploy

**Deploy readiness:** เดิม **0%** (build ไม่ผ่านเลย) → ตอนนี้ยกสแตกขึ้นได้จริงและผ่านการตรวจ 8 ข้อ
เหลือแต่การยืนยันบนฮาร์ดแวร์จริง

**ระยะรวม:** พร้อมขึ้น VM ทดลองใช้จริงได้แล้ว ที่เหลือเป็นงานยืนยันบนเครื่องจริง ไม่ใช่งานเขียนโค้ด

## หมายเหตุ / ความเสี่ยง ⚠️

- **`FRONTEND_URL` ใน `.env` ต้องเป็น IP ที่ผู้ใช้พิมพ์ในเบราว์เซอร์จริง** ไม่ใช่ `localhost`
  ตั้งผิดแล้วลิงก์ยืนยันอีเมล/รีเซ็ตรหัสผ่านจะพาผู้ใช้ไปผิดที่ (ตรวจก่อนเปิดให้คนอื่นใช้)
- **ถ้า SMTP ยังใช้ไม่ได้แล้วจำเป็นต้องตั้ง `DEV_AUTO_VERIFY_EMAIL=true` ชั่วคราว
  ต้องปิดหน้าสมัครเองควบคู่ไปด้วย** ให้แอดมินสร้างบัญชีผ่าน `POST /users` แทน
  ไม่งั้นใครก็สมัครด้วยอีเมล `@cdti.ac.th` ที่ไม่ใช่ของตัวเองแล้วเข้าใช้ได้ทันที (CLAUDE.md ข้อ 10)
- **`ALLOWED_EMAIL_DOMAINS` ยังไม่ได้ยืนยันกับอาจารย์เป็นลายลักษณ์อักษร** (ค้างมาหลายรอบ, CLAUDE.md ข้อ 10)
- **`--workers 1` เป็นเรื่องตั้งใจ ห้ามเพิ่มโดยไม่แยก scheduler ออกเป็น service ก่อน**
  ไม่งั้นอีเมลทวงของเกินกำหนดจะส่งซ้ำตามจำนวน worker ทุกคืน
- **`backend/.env` เป็นไฟล์ของ dev อย่างเดียวแล้ว** prod ใช้ `.env` ที่ root และ `.dockerignore`
  กันไม่ให้ติดไปกับ image — อย่าเผลอเอา `env_file: ./backend/.env` กลับมา
- ยังไม่มี TLS (LAN คณะจึงยอมรับได้), ยังไม่มี CI, `requirements.txt` ยัง `>=` ทั้งหมด
  — ทั้งหมดตัดสินใจข้ามพร้อมเหตุผลและเงื่อนไขที่ต้องกลับมาทำ บันทึกไว้ใน `DEPLOY-PLAN.md`
- **`frontend/.env` ยังชี้ `http://192.168.1.164:8000`** ไม่ได้แก้เพราะ dev ใช้ได้อยู่
  ถ้าอยากให้ dev เหมือน prod เปลี่ยนเป็น `/api` ได้ (vite proxy รองรับอยู่แล้ว)
