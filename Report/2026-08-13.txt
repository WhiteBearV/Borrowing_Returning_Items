### QA รอบใหญ่บนระบบจริง (http://172.16.46.10/)
ทดสอบ end-to-end ครบทุก flow หลักตาม Business Rules ใน CLAUDE.md §5:
- ยื่นคำขอ (durable/material + consumable ผสมกัน) → อนุมัติ (เช็คสต็อกลดถูกต้องทั้งสองชนิด) → ต่อเวลา (ทดสอบผ่าน API ตรง เพราะเจอบั๊ก UI — ดูตารางปัญหา) → คืนของ (`used_up` ไม่คืนสต็อก / `ok` คืนสต็อกเต็ม ตรงตาม `borrow_service.py`) → request เป็น `completed` อัตโนมัติเมื่อครบทุก item
- ดาวน์โหลด PDF ใบยืม + ใบรับคืน (`GET /borrow-requests/{id}/pdf`, `/return-pdf`) ตรวจเนื้อหาแล้วถูกต้องครบทุกฟิลด์ (หน่วย/จำนวน/สภาพ/ผู้รับคืน)
- Audit log บันทึกครบทุก action (`approve`, `return` ×2) พร้อม actor snapshot ตรงตาม `audit_service.log_action`
- Edge case ยิงตรงผ่าน API ยืนยันครบ: บล็อกยืมของ `quantity_available=0` (400), บังคับแนบ `damage_photo_urls` ตอนแจ้ง `lost`/`damaged` (400 ไม่มีรูป → 200 มีรูป), บล็อกเกิน `max_items_per_request=5` (400), บล็อกเกิน `max_active_requests_per_student=2` (400)
- ทดสอบสมัครสมาชิกผ่านหน้าเว็บจริง (`RegisterPage.jsx`) → auto-verify เพราะ `DEV_AUTO_VERIFY_EMAIL=true` → login เข้าใช้ได้ทันที ไม่ติดกับดัก "เช็คอีเมล" ที่เคยกังวลไว้
- เก็บกวาดข้อมูลทดสอบออกจาก DB จริงหลัง QA เสร็จ: ลบ 3 คำขอทดสอบ, คืนสต็อก `613001`/`CON-WIRE-001` กลับค่าเดิม, ลบบัญชีทดสอบ `6699999999@cdti.ac.th` (รวม `auth_tokens` ที่ผูกอยู่)

### Frontend — Mobile/Tablet Responsive (แก้ตามรายงานผู้ใช้จริงจากมือถือ)
- **`frontend/src/components/layout/Sidebar.jsx`** — เดิม `w-56` ตายตัวไม่มี responsive breakpoint เลย เปลี่ยนเป็น off-canvas drawer: ซ่อนไว้นอกจอใต้ `md` breakpoint, เปิดด้วยปุ่ม hamburger, มี backdrop กดปิด, แตะลิงก์เมนูปิดอัตโนมัติ
- **`frontend/src/components/layout/ProtectedRoute.jsx`** — เพิ่ม topbar มือถือ (ปุ่ม hamburger + ชื่อระบบ) คุม state เปิด/ปิด sidebar ร่วมกัน
- แก้บั๊ก **เลื่อนไม่ถึงปุ่มออกจากระบบ**: `h-screen` (100vh) ชนกับ `inset-y-0` บน `position:fixed` — `height` ที่ระบุตรงชนะ `bottom:0` เสมอ ทำให้ยังอิงหน่วย `vh` ที่มีบั๊กกับ address bar มือถือ (พื้นที่มองเห็นจริงน้อยกว่า 100vh) แก้โดยตัด `h-screen` ออกจากฝั่งมือถือ เหลือ `inset-y-0` เพียว ๆ ซึ่งยึดตาม viewport จริงเสมอ คงไว้แค่ `md:h-screen` สำหรับจอใหญ่ที่เป็น `sticky`
- แก้บั๊ก **`<select>` หมวดหมู่ล้นขอบจอ** — form control ไม่ยอม shrink ต่ำกว่า content width เริ่มต้นใน flex row (ปัญหา flexbox คลาสสิก) เจอ pattern เดียวกันซ้ำ 4 หน้า: `EquipmentListPage.jsx`, `EquipmentManagePage.jsx`, `UsersPage.jsx`, `AllBorrowsPage.jsx` แก้เป็น stack แนวตั้งบนมือถือ (`flex-col sm:flex-row`) + cap ความกว้าง select ตอนเรียงแถวจอใหญ่
- แก้ **`EquipmentManagePage.jsx`/`BundleManagePage.jsx`** — header มีปุ่ม 4 ปุ่มเรียงแถวเดียวไม่มี wrap เพิ่ม `flex-wrap` + stack กับ title บนมือถือ
- แก้ **`frontend/index.html`** — browser tab title ยังเขียน "KMITL" ทั้งที่โปรเจกต์นี้เป็นของ CDTI (สถาบันเทคโนโลยีจิตรลดา) เปลี่ยนเป็น "CE & DD CDTI" — เช็คทั้งโปรเจกต์แล้วเป็นจุดเดียวที่หลุด (PDF/email domain ถูกต้องอยู่แล้ว)
- Deploy ขึ้น VM จริงรวม 4 รอบระหว่างวัน (commit `300cf07`, `823345a`, `343a895`, `1dfac0e`) ตามที่ทดสอบเจอปัญหาเพิ่มทีละจุดจากอุปกรณ์จริง

## สถานะโดยรวม

**Backend:** ~98% — endpoint และ business rule ครบตาม `02-system-design.md` ทั้งหมด ผ่าน QA จริงบน production ครบทุก flow หลักและ edge case สำคัญ ไม่พบบั๊ก backend ใหม่วันนี้เลย (บั๊กที่พบเป็นฝั่ง frontend ล้วน)
**Frontend:** ~95% — mobile responsive แก้ไปหลายจุดใหญ่วันนี้ (sidebar drawer, filter overflow, header wrap) เหลือ 1 จุดที่ยังไม่ยืนยันว่าหายจริง (admin scroll) + บั๊กเล็ก 1 จุดที่เลื่อนไว้ (ปุ่มต่อเวลา material)
**ระยะรวม:** ระบบขึ้น production จริงบน Proxmox VM แล้ว พร้อมข้อมูลอุปกรณ์จริงครบ 1,256 รายการ (ย้ายจาก dev DB) วันนี้เป็นวันแรกที่ทดสอบผ่านมือถือจริงและพบว่า UI เดิมใช้ไม่ได้เลยบนอุปกรณ์อื่นนอกจากคอม — ถือเป็นความเสี่ยงสำคัญที่เจอทันเวลาก่อนเปิดให้นักศึกษาใช้จริงเป็นวงกว้าง
