## สิ่งที่ทำสำเร็จวันนี้ ✅

### Backend
- **Endpoint สร้างผู้ใช้ (admin เท่านั้น)** — เพิ่ม `POST /users` สร้างได้ทั้ง student และ admin
  - `schemas/user.py`: เพิ่ม `UserCreateRequest` (email, full_name, password, role, username, student_id, major)
  - `services/users_service.py`: เพิ่ม `create_user()` — เช็คอีเมล/รหัสนักศึกษาซ้ำ, hash password, verified ทันที
  - `routers/users.py`: route `POST /users` ครอบด้วย `require_admin`
- **Image upload + แกลเลอรี่หลายรูป**
  - `models/equipment.py`: เพิ่มคอลัมน์ `image_urls` (JSON list), `image_url` เดิมกลายเป็น cover (รูปแรก) sync อัตโนมัติ
  - `alembic/versions/0005_equipment_image_urls.py`: migration เพิ่มคอลัมน์ + backfill รูปเดิม (รันแล้ว)
  - `services/equipment_service.py`: เพิ่ม `save_image()` (จำกัดนามสกุล jpg/png/webp/gif + ขนาด ≤5MB), sync cover ใน create/update
  - `routers/equipment.py`: `POST /equipment/upload-image`
- **จัดการหมวดหมู่ (admin)** — เพิ่ม `update_category()` (เปลี่ยนชื่อ) และ `delete_category()` (กันลบถ้ายังมีอุปกรณ์ผูกอยู่) + routes `PATCH/DELETE /equipment-categories/{id}`
- **เรียงลำดับอุปกรณ์** — `list_equipment()` เพิ่ม `ORDER BY (status=available AND qty>0) DESC, name` → ของยืมได้ขึ้นก่อน ยืมไม่ได้กองท้าย (ครอบทุกหน้า pagination)
- **แก้ test ให้ cleanup ตัวเอง** — `tests/test_api_integration.py::test_equipment_multiple_categories` ลบ equipment/category/M2M links ที่สร้างท้ายเทสต์ (รันผ่าน ไม่มี junk ค้าง)

### Frontend
- **หน้า Login** (`pages/LoginPage.jsx`): ปุ่มกดค้างเพื่อโชว์รหัสผ่าน (กด=เห็น ปล่อย=ซ่อน)
- **หน้าจัดการผู้ใช้** (`pages/admin/UsersPage.jsx`): ปุ่ม "+ เพิ่มผู้ใช้" + modal (สลับ student/admin, ช่องชื่อ-นามสกุลแยก, กรอก student_id/major หรือ username)
- **หน้าจัดการอุปกรณ์** (`pages/admin/EquipmentManagePage.jsx`):
  - อัปโหลดหลายรูป (ต่อท้ายไม่ทับ) + preview + ป้าย "ปก" + ปุ่มลบทีละรูป
  - เพิ่มคอลัมน์รูป (thumbnail) ในตาราง
  - ช่องเลือก status ใน modal แก้ไข (พร้อม/ไม่อนุญาต/เสียหาย/ซ่อม/ปลดระวาง)
  - modal "จัดการหมวดหมู่" (เพิ่ม/เปลี่ยนชื่อ/ลบ)
  - เพิ่ม helper `errMsg()` แปลง error 422 (array) เป็น string กัน React จอขาว
- **หน้ารายการอุปกรณ์ (นักศึกษา)** (`pages/student/EquipmentListPage.jsx`):
  - เก็บ filter (คำค้น/หมวด/หน้า) ไว้ใน URL → กดย้อนกลับแล้วหมวดเดิมยังอยู่
  - รูปการ์ด `object-contain` (ไม่โดน crop)
  - badge สถานะอ่านจาก `status` จริง (unavailable/damaged/หมด) ไม่เดามั่วว่า "ถูกยืมอยู่"
- **หน้ารายละเอียด (นักศึกษา)** (`pages/student/EquipmentDetailPage.jsx`): แกลเลอรี่รูปใหญ่ `object-contain` + ปุ่มลูกศร ‹ › + thumbnail strip + badge/เหตุผลตาม status
- **api** (`equipmentApi.js`, `usersApi.js`): เพิ่ม uploadImage, updateCategory, deleteCategory, users.create

## ปัญหาที่พบ / ปัญหาที่ยังค้างอยู่ 🔴

| ปัญหา | สาเหตุ | วิธีแก้ / แผน |
|---|---|---|
| ล็อกอิน admin ไม่ได้ (401) | บัญชี admin ไม่มี username/student_id + จำรหัสไม่ได้ | รีเซ็ตรหัส + เติม username=Admin (แก้แล้ว) |
| อัปโหลดรูปแล้วจอขาว | axios ตั้ง Content-Type=json → FormData ไม่มี boundary + error 422 เป็น array render ตรง ๆ | override header multipart + `errMsg()` (แก้แล้ว) |
| เลือกหมวดในหน้านักศึกษาไม่ได้ | handler เรียก setPage(1) ต่อท้าย เขียนทับ URL param ที่เพิ่ง set (อ่าน prev เก่า) | เอา setPage(1) ที่ซ้ำออก (แก้แล้ว) |
| ของ status=unavailable ขึ้น "พร้อมให้ยืม"/"ถูกยืมอยู่" ผิด | frontend ไม่รู้จักค่า status `unavailable` เดาจาก qty=0 | อ่าน status เป็นหลัก (แก้แล้ว) |
| `equipment.status` ไม่เปลี่ยนเป็น borrowed ตอนของถูกยืมหมด | borrow_service ลดแค่ quantity_available | frontend คำนวณเอาถูกแล้ว; ถ้าจะ sync field status ด้วยต้องแก้ borrow_service (ยังไม่ทำ) |
