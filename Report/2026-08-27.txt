วันนี้ implement 3 ฟีเจอร์ใหม่ตามที่ผู้ใช้ขอ (วางแผนผ่าน Plan Mode ก่อน) → เขียนเทสคู่กันทุกจุด → รัน **Full QA จำลอง 3 persona** ทั้งระบบก่อน commit → เจอบั๊กจริง 1 ตัวระหว่าง QA แล้วแก้ทัน → commit 2 ครั้ง + push ขึ้น `origin/main` แล้ว (`42e4091`, `b7bd9b5`) **ยังไม่ deploy ขึ้น production**

### Backend

**1. ต่อเวลาแบบขออนุมัติ** (เปลี่ยน business rule เดิมทั้งหมด — ดู CLAUDE.md หัวข้อ "การต่อเวลา" ที่แก้ไปด้วย)
- **`app/models/borrow_item.py`**: เพิ่ม 5 คอลัมน์ `renew_requested`, `renew_requested_at`, `renew_requested_date`, `renew_reason`, `renew_rejected_reason`
- **`alembic/versions/0022_renew_request_fields.py`** (ใหม่): เพิ่มคอลัมน์ข้างต้น + data migration แก้ description ของ setting `max_renew_days` ให้ตรงความหมายใหม่
- **`app/services/borrow_service.py`**: ลบ `renew_item()` เดิม (ต่อทันทีทีเดียว) แทนด้วย `request_renew_item()` (นักศึกษายื่นคำขอ เช็ค `max_renew_count` ตอนขอทันที + เพดานวันล่วงหน้าจาก `max_renew_days`), `approve_renew_item()`, `reject_renew_item()` (admin เท่านั้น) — เพิ่ม helper `_find_item()`/`_recompute_overdue()` ใช้ร่วม 3 ฟังก์ชัน
- **`app/routers/borrow.py`**: ลบ `POST .../renew` แทนด้วย `POST .../renew-request`, `POST .../renew-approve`, `POST .../renew-reject`
- **`app/schemas/borrow.py`**: เพิ่ม `RenewRequestCreate`, `RenewRejectRequest`, เพิ่ม 5 ฟิลด์ใน `BorrowItemResponse`

**2. Search bar หน้าประวัติการยืม**
- **`app/services/borrow_service.py` — `list_requests()`**: เพิ่ม param `search` — join `User` ค้น `full_name`/`student_id` + EXISTS subquery ค้น `BorrowItem.equipment_name` ผ่าน `ilike`
- **`app/routers/borrow.py`**: เพิ่ม query param `search` ใน `GET /borrow-requests`

**3. ปุ่ม "ปรับยอดคงเหลือ"** (แยกจาก "+ เพิ่มจำนวน" เดิมที่ยังทำงานแบบเดิมไม่แตะ)

- **`app/routers/equipment.py`**: เพิ่ม `POST /equipment/{id}/adjust-stock`

### บั๊กที่เจอระหว่าง Full QA แล้วแก้ (`b7bd9b5`)

- **`hooks/useBorrowCart.js` — `addBundle()`**: toast "เพิ่มชุดลงตะกร้าแล้ว — ยกเว้น ..." ไม่เคยขึ้นจริงตั้งแต่แรก แม้ของในชุดจะหมดสต็อกจริง สาเหตุ: เดิม push รายการที่ข้ามเข้า `skipped` array **ข้างใน** callback ที่ส่งให้ `setCart()` แต่ React ไม่เรียก callback นั้นทันที (รอตอน re-render) → `return skipped` ข้างนอกได้ array ว่างเปล่าเสมอ แก้โดยแยกคำนวณเป็นฟังก์ชันบริสุทธิ์ `bundleSkippedNames()` ใน **`hooks/cartRules.js`** ที่รันก่อนเรียก `setCart` เสมอ

## หมายเหตุ / ความเสี่ยง ⚠️

- **Migration ใหม่ (`0022`)**: deploy พรุ่งนี้ต้อง backup DB ก่อนเสมอ — เพิ่มคอลัมน์ nullable ทั้งหมด (ความเสี่ยงต่ำ) แต่มี data migration แก้ description ของ setting `max_renew_days` ด้วย ต้องเช็คว่า apply สำเร็จหลัง deploy
- **Breaking change ที่ workflow ต่อเวลา**: นักศึกษาที่คุ้นเคยกับปุ่ม "ต่อเวลา" แบบกดแล้วได้ทันที จะเจอ UX ใหม่ที่ต้องรอ admin อนุมัติ — ควรมีการสื่อสารล่วงหน้าก่อน deploy จริง ไม่ใช่แค่ deploy เงียบ ๆ
- **`max_renew_days` เปลี่ยนความหมาย**: จาก "จำนวนวันที่บวกอัตโนมัติ" (ตอนนี้กลายเป็น "เพดานวันล่วงหน้าที่ขอได้") — ค่าเดิม `7` ยังใช้ได้พอดีโดยไม่ต้องปรับ แต่ถ้าแอดมินเคยเข้าใจความหมายเดิมของ setting นี้ ควรอธิบายใหม่ให้ตรงกับ description ที่แก้ในหน้า Settings แล้ว
- **Pending items เดิมจาก CLAUDE.md ข้อ 10** ยังไม่มีความคืบหน้าเพิ่มวันนี้ (ไฟล์ Excel คลังอุปกรณ์เดิมรอทีมอื่นส่ง, ยืนยัน `ALLOWED_EMAIL_DOMAINS` กับอาจารย์ก่อน deploy จริง, LINE OA ยังเป็น stretch goal)
