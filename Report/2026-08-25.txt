### ช่วงที่ 1 — แก้บั๊ก 3 ข้อ + ฟีเจอร์เสริม 2 อย่าง (deploy แล้ว, commit `677785b`)

**Backend**
- **`app/services/equipment_service.py` — `update_equipment`**: บั๊กจริงที่ผู้ใช้รายงาน — แก้สถานะจาก "ไม่อนุญาตให้ยืม" กลับเป็น "ให้ยืม" แล้ว `quantity_available` ไม่คืนค่า ค้าง 0 ตลอดไป (ไม่มีช่องแก้ตรง ๆ ที่ไหนเลย) สาเหตุคือ `update_equipment` มีแต่ down-clamp ไม่มี up-restore แก้ให้ (1) เพิ่ม `quantity_total` แล้วคืนค่าคงเหลือตามส่วนต่างอัตโนมัติ (2) แก้ `status` กลับเป็น `available` จากของหาย/เสีย (`quantity_total==1`) คืนค่าคงเหลือให้ครบ
- **`app/services/import_service.py` — `commit_import` (action=update)**: พบต้นตอบั๊กสต็อกเพี้ยนของ `Sw_Push001`/`LED-7_Segment_Common_Cathod01` ที่ผู้ใช้รายงานว่าแยกเป็นรายชิ้น/ยืมไม่ได้ — นำเข้าทะเบียนซ้ำแล้วจำนวนรวมเปลี่ยน เดิมตั้งค่า `quantity_available` ทับตรง ๆ (`= row.quantity` หรือ `0`) ทิ้งจำนวนที่ยืมอยู่จริง ณ ตอนนั้นไป แก้เป็นขยับตามส่วนต่าง (delta) แทน — จุดนี้สำคัญเพราะเป็นจุดเดียวกับที่จะโดนซ้ำตอนนำเข้าไฟล์ Excel คลังเดิมตามแผนที่ค้างไว้ (CLAUDE.md ข้อ 10)
- **`app/services/equipment_service.py` — เพิ่ม `restock_equipment`**: ฟีเจอร์ใหม่ตามคำขอ — พิมพ์แค่ "จะเพิ่มกี่ชิ้น" ระบบตัดสินเองว่าบวกเข้าแถวเดิม (วัสดุสิ้นเปลือง/วัสดุก้อนที่ยังไม่แยกรายชิ้น) หรือสร้างแถวใหม่แยกรหัส (ครุภัณฑ์/วัสดุที่แยกแล้ว) แก้ปัญหาที่ฟอร์มแก้ไขเดิมเป็นค่าสัมบูรณ์ พิมพ์ผิดแล้วสต็อกหายได้
- **`app/services/equipment_service.py` — เพิ่ม `bulk_retire_equipment`**: ปลดระวางหลายรายการพร้อมกันแบบ best-effort (ตามคำขอ ปุ่มคั่นกลาง "แก้ไขหลายรายการ"/"ลบถาวรที่เลือก")
- **`app/routers/equipment.py`**: เพิ่ม `POST /equipment/{id}/restock`, `POST /equipment/bulk-retire`
- **`app/schemas/equipment.py`**: เพิ่ม `RestockRequest`, `BulkRetireRequest`, `BulkRetireResult`

**Frontend**

## หมายเหตุ / ความเสี่ยง ⚠️

- **Migration ใหม่ (`0021`)**: deploy พรุ่งนี้ต้อง backup DB ก่อนเสมอ (ตามแนวทางเดิมที่เคยทำตอน migration `0020`) แม้จะเป็นแค่เพิ่มคอลัมน์ nullable ความเสี่ยงต่ำ แต่เป็น production DB ที่มีผู้ใช้จริง
- **`audit_interval_days=180` เป็นค่า default ที่ยืนยันกับผู้ใช้แล้วในบทสนทนา** แต่ยังไม่ได้ยืนยันอย่างเป็นทางการกับอาจารย์ที่ปรึกษาหรือฝ่ายพัสดุของคณะว่าตรงกับรอบตรวจครุภัณฑ์จริงหรือไม่ — ปรับได้ทีหลังในหน้า Settings โดยไม่ต้อง migration ใหม่ ความเสี่ยงต่ำ
- **ฟีเจอร์ตรวจนับกายภาพเป็นของใหม่ทั้งหมด**: อุปกรณ์ทุกชิ้นในคลัง (~1,455 รายการนับทั้งกลุ่ม) จะขึ้น "ครบกำหนดตรวจนับ" พร้อมกันหมดตั้งแต่วันแรกที่ deploy เพราะไม่เคยมีการบันทึกตรวจนับมาก่อนเลย — คาดว่า dashboard tile จะโชว์เลขใหญ่ผิดปกติช่วงแรก ควรอธิบายให้ผู้ใช้/แอดมินเข้าใจก่อนตกใจว่าเป็นบั๊ก
- **Snipe-IT เก่า (172.16.46.64)**: สำรวจแล้วพบว่ามีฟีเจอร์อื่นที่ยังไม่ได้เอามาใช้ (เช่น bulk checkout, maintenance log) ซึ่งประเมินว่ายังไม่คุ้ม/นอกขอบเขตเฟสนี้ (ตรง CLAUDE.md ข้อ 11 เรื่องขอบเขต) — ถ้าอยากทำต่อควรแยกเป็นแผนใหม่
