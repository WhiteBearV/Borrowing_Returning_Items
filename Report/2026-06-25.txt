## สิ่งที่ทำสำเร็จวันนี้ ✅

### Backend
- `backend/app/schemas/auth.py` — ปรับ `student_id` และ `major` ใน `RegisterRequest` ให้เป็น required field (ไม่ใช่ Optional อีกต่อไป)
- `backend/app/services/auth_service.py` — เพิ่ม auto-verify email ในโหมด dev (เมื่อ SMTP ไม่ได้ตั้งค่า) ผ่าน flag `_email_configured`
- `backend/app/utils/email.py` — เพิ่ม dev mode: ถ้า `MAIL_USERNAME` เป็น placeholder จะ print token ลง console แทนส่งจริง ไม่ทำให้ระบบ crash
- `backend/app/core/security.py` — แก้ปัญหา bcrypt version incompatibility กับ passlib โดย downgrade `bcrypt==4.0.1`
- `backend/scripts/import_equipment.py` — เขียน migration script สำหรับดึงข้อมูลอุปกรณ์จาก Snipe-IT (MySQL) → PostgreSQL พร้อม status mapping และ category dedup
- `backend/alembic/versions/` — รัน migration สร้างตาราง (`0001_initial_schema`, `0002_seed_settings`) สำเร็จ
- `.env` — ตั้งค่า `SECRET_KEY` และเพิ่ม `cdti.ac.th` ใน `ALLOWED_EMAIL_DOMAINS`

### Frontend
- `frontend/src/pages/RegisterPage.jsx` — แยกช่อง ชื่อ/นามสกุล เพิ่มช่องคำนำหน้า (นาย/นาง/นางสาว) บังคับกรอกรหัสนักศึกษา 10 หลัก (`pattern="\d{10}"`) และบังคับเลือกสาขา

### Database / Data
- Import ข้อมูลอุปกรณ์จากระบบ Snipe-IT เดิม (fdt-asset-server) สำเร็จ
  - Equipment: **1,103 รายการ** (available 896, unavailable 203, damaged 4)
  - Categories: **12 หมวดหมู่**
- สร้าง admin account: `admin@cdti.ac.th` พร้อมใช้งาน

## ปัญหาที่พบ / ปัญหาที่ยังค้างอยู่ 🔴

| ปัญหา | สาเหตุ | วิธีแก้ |
|---|---|---|
| `bcrypt==5.0.0` ไม่ compatible กับ `passlib` | passlib ยังไม่รองรับ bcrypt 4.x+ API | downgrade เป็น `bcrypt==4.0.1` |
| SSH เข้า fdt-asset-server ด้วย hostname ไม่ได้ | DNS resolve ล้มเหลวใน local network | ใช้ IP ตรง (172.16.46.64) แทน |
| `status_labels` ใน Snipe-IT เสีย (id 9–36 เป็น concatenated string) | bug การใช้งาน Snipe-IT เดิม | ใช้ name-based fallback ใน migration script |
| Email verification ใช้ไม่ได้ใน dev | SMTP ยังไม่ตั้งค่า | auto-verify ใน dev mode + print token ลง console |
