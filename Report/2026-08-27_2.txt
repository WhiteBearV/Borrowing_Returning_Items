**2. บังคับรหัสครุภัณฑ์ 15 หลักตอนเปลี่ยนเป็น "ครุภัณฑ์"**
- **`app/services/equipment_service.py`**: เพิ่ม `_validate_durable_code()` (นับเฉพาะตัวเลขในรหัส ต้องได้ 15 หลักพอดี) เรียกใช้ใน `create_equipment`, `update_equipment` (เฉพาะตอนเปลี่ยน**เข้า**ครุภัณฑ์เท่านั้น ไม่เช็คของเดิมที่เป็นครุภัณฑ์อยู่แล้ว), `bulk_update_equipment` (partial-success — แถวไหนรหัสไม่ผ่านถูกใส่ลง `failed[]` ไม่ทำให้ทั้ง batch ล้ม)
- **`app/schemas/equipment.py`**: เพิ่ม `failed: list[BulkDeleteFailure]` ใน `BulkUpdateResult`

**3. รวม `is_borrowable` เข้ากับสถานะที่กรอง/แสดง** (แก้บั๊ก "ของประจำห้องขึ้นพร้อมให้ยืม")
- **`app/services/equipment_service.py` — `_apply_status_filter`**: `available` ต้องเช็ค `is_borrowable=True` ควบด้วย, `unavailable` เป็น `status=="unavailable" OR is_borrowable=False`

**4. แก้บั๊กผู้ยืมพร้อมกันหลายคนถูกทับเหลือคนเดียว (consumable)**
- **`app/services/equipment_service.py` — `get_holders_map`**: เปลี่ยน return type `dict[UUID, HolderInfo]` → `dict[UUID, list[HolderInfo]]` (ของเดิม dict comprehension ทับกันเหลือคนสุดท้าย) + เพิ่ม `.order_by(User.full_name, BorrowItem.id)` ให้ลำดับ deterministic — อัปเดตทุกจุดที่เรียกใช้ (`list_equipment`, `_build_group_response`, `get_equipment_group_detail`)
- **`app/schemas/equipment.py`**: เพิ่ม `holders: list[HolderInfo]` ใน `EquipmentResponse`

**5. เพิ่ม endpoint ปรับยอดคงเหลือหลายรายการแบบ delta**
- **`app/services/equipment_service.py` — `bulk_adjust_stock()`** (ใหม่): บวก/ลบเท่ากันทุกแถวที่เลือก, clamp ต่อแถว `0 <= available <= quantity_total - outstanding_qty` (หักจำนวนที่ถูกยืมออกไปจริงด้วย ไม่ใช่แค่ `quantity_total` เฉยๆ — **จุดนี้ Opus code review เจอเป็นบั๊ก HIGH ก่อน commit จริง**: ถ้าไม่หัก ตอนคืนของทีหลังจะชน DB CHECK constraint คืนไม่ได้เลย), ล็อกแถวเรียงตาม `Equipment.code` ให้ตรงกับ `borrow_service.approve_request` กัน deadlock, dedupe id ซ้ำ, partial-success (`failed[]`) เหมือน bulk อื่น
- **`app/schemas/equipment.py`**: `BulkAdjustStockRequest`/`BulkAdjustStockResult`
- **`app/routers/equipment.py`**: เพิ่ม `PATCH /equipment/bulk-adjust-stock` (`require_admin`)
- เพิ่มไฟล์เทสใหม่ 4 ไฟล์: `test_equipment_durable_code_validation.py`, `test_equipment_is_borrowable_filter.py`, `test_equipment_multiple_holders.py`, `test_equipment_bulk_adjust_stock.py`

**6. แก้เศษข้อมูลทดสอบค้างที่เจอระหว่าง QA**
- **`tests/test_user_delete.py`**: `test_delete_admin_who_approved_other_students_request` cleanup เดิมอยู่ใน happy path เท่านั้น (ลบ user ผ่าน API ใน try block) ถ้า assert พังกลางทางจะค้างถาวร — เพิ่ม fallback ลบซ้ำใน `finally` เจอ+ลบเศษบัญชีค้างจริง 2 แถว (`deltest_*`) ออกจาก dev DB แล้ว (เช็คไม่มี FK อ้างอิงก่อนลบ)
