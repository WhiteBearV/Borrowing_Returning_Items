## สิ่งที่ทำสำเร็จวันนี้ ✅

### Backend

**1. ฟีเจอร์ต่อเวลา (renew) — ขยายสิทธิ์ + หน้าคำขอของ admin**
- `services/borrow_service.py::list_requests` — เพิ่มพารามิเตอร์ `own_only: bool = False`
  บังคับกรองเฉพาะคำขอของตัวเองแม้ role เป็น admin (เดิม admin เห็นคำขอทุกคนเสมอ)
  เงื่อนไขใหม่: `if current_user.role != "admin" or own_only`
- `routers/borrow.py::list_borrow_requests` — ส่งผ่าน `own_only: bool = Query(False)`
  ตาม pattern ชื่อ `_only` เดิม (`overdue_only`) ค่า default False หน้า "ประวัติการยืมทั้งหมด" ไม่กระทบ
- ตรวจสอบแล้วว่า `request_renew_item` ไม่มีเงื่อนไข item_type อยู่แล้ว → รองรับ durable/material/consumable
  ได้ทันทีโดยไม่ต้องแก้ backend (ข้อจำกัดอยู่ฝั่ง frontend จุดเดียว)

**2. อีเมลแจ้งอนุมัติคำขอ — แนบรูป + รายละเอียดอุปกรณ์ทุกชิ้น**
- `services/borrow_service.py` — เพิ่ม helper `_build_item_row_html(item)` สร้าง HTML card ต่ออุปกรณ์ 1 ชิ้น
  (รูปจาก `item.equipment.image_url` ต่อกับ `settings.APP_BASE_URL`, ถ้าไม่มีรูปใช้กล่องเทา "ไม่มีรูปภาพ"
  กัน broken image) + ตาราง ชื่อ/รหัส/จำนวน
- `approve_request` — เปลี่ยนเนื้ออีเมลจาก `<p>` บรรทัดเดียว เป็นหัวข้อ "สวัสดี {ชื่อ}" + ข้อความอธิบาย
  + card ของทุกชิ้นในคำขอ (subject คงเดิมเพื่อให้ค้นใน inbox ได้)
- เพิ่ม import `from app.core.config import settings` ในไฟล์นี้ (เดิมไม่มี)

**3. ใบยืม PDF — โชว์รหัสวัสดุสิ้นเปลืองเสมอถ้ามีค่า**
- `utils/pdf.py::_build_form` — ลบ special-case `if itype == "consumable": code_display = "-"` ทิ้ง
  ให้ใช้ logic เดียวกับ durable/material พร้อมลบ comment ที่อธิบายพฤติกรรมเก่าที่ถูกลบไปแล้ว

**4. เบอร์โทรศัพท์ + ยินยอม PDPA**
- `models/user.py` — เพิ่มคอลัมน์ `phone` (String(20), nullable) และ `pdpa_consent_at`
  (DateTime timezone, nullable) — nullable ระดับ DB เพราะบัญชีที่ admin สร้างไม่ผ่านฟอร์มสมัคร
- `alembic/versions/0025_user_phone_pdpa_consent.py` (ไฟล์ใหม่) — add_column 2 คอลัมน์ (apply เข้า dev DB แล้ว)
- `schemas/auth.py::RegisterRequest` — เพิ่ม `phone` (pattern `^0\d{9}$`) reuse `_strip_student_id`
  เป็น `_normalize_phone`, เพิ่ม `pdpa_consent: bool` + `field_validator` ปฏิเสธถ้าไม่ True
  (บังคับฝั่ง backend จริง ไม่เชื่อแค่ frontend)
- `services/auth_service.py::register` — บันทึก `phone` + `pdpa_consent_at = datetime.now(timezone.utc)`
- `schemas/user.py` — `UserCreateRequest` เพิ่ม `phone` (ไม่บังคับ) + `UserResponse` เพิ่ม `phone`
- `services/users_service.py::create_user` — บันทึก `phone` ที่ admin กรอก

**5. QR Code — URL เปลี่ยนตามเครื่องอัตโนมัติ + ปิดช่องโหว่ security**
- `services/equipment_service.py::generate_qr` — รับพารามิเตอร์ `frontend_origin: str | None = None`
  ใช้แทน `settings.FRONTEND_URL` คงที่ถ้ามีค่า
- `routers/equipment.py` — เพิ่ม `_is_lan_host()` + `_forwarded_frontend_origin()` อ่าน
  `X-Forwarded-Host`/`X-Forwarded-Proto` มาสร้าง origin โดย**ยอมรับเฉพาะ address ในวง LAN/loopback**
  (ใช้ `ipaddress.ip_address().is_private` ของ stdlib) กันการปลอม header ยัดโดเมนฟิชชิ่งลง QR
- เพิ่ม `Cache-Control: no-store` ให้ response ของ QR (กัน browser cache รูป QR ที่ฝัง IP เก่า)

## หมายเหตุ / ความเสี่ยง ⚠️

- **`FRONTEND_URL` ค้างเป็น IP เก่า (172.20.57.146)** — กระทบลิงก์ยืนยันอีเมล/รีเซ็ตรหัสผ่าน และ
  CORS `allow_origins` ถ้าเทสสมัครสมาชิกจริงต้องแก้ก่อน (QR ไม่กระทบแล้วเพราะใช้ค่าจาก request แทน)
- **QR code จะฝัง host ตามที่เปิดหน้าแอดมิน** — ถ้าเปิดด้วย localhost จะได้ QR ที่มือถือสแกนไม่ได้
  ต้องเปิดด้วย LAN IP เสมอเวลาจะพิมพ์ QR ไปแปะของจริง
- **การเก็บเบอร์โทรศัพท์ = ข้อมูลส่วนบุคคลตาม PDPA** — ตอนนี้มี checkbox ยินยอม + บันทึกเวลาที่ยินยอม
  (`pdpa_consent_at`) แล้ว แต่ข้อความคำชี้แจงที่ได้มาอ้างถึง "แบบประเมิน" ซึ่งเป็นบริบทคนละอันกับระบบยืม-คืน
  ควรปรับข้อความให้ตรงบริบทก่อนใช้งานจริง
- **Pending Items ตาม CLAUDE.md ข้อ 10 ที่ยังค้าง:** ยืนยัน `ALLOWED_EMAIL_DOMAINS` กับอาจารย์ก่อน deploy จริง
  และ LINE OA Channel Access Token (stretch goal ยังไม่เริ่ม)
- เทสรันกับ DB dev จริง (`PYTEST_ALLOW_DB=1`) — เทสใหม่ทุกไฟล์ cleanup ครบใน finally แล้ว
