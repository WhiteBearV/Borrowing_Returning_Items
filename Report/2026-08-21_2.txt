### Deploy ขึ้นเซิร์ฟเวอร์จริง — IP เปลี่ยนเป็น 172.16.46.130

- เซิร์ฟเวอร์จริง (VM `DockerMaeb`) เปลี่ยน IP จาก `172.16.46.10` → `172.16.46.130` ระหว่างวัน
- ตรวจพบว่าโค้ดบนเซิร์ฟเวอร์ค้างอยู่ที่ commit `1dfac0e` (ตามหลัง main 8 commits รวมถึง TLS setup)
- `git pull` → ขึ้นถึง `b2ceda3` สำเร็จ, migration ขึ้นถึง `0019 (head)`
- ออก self-signed TLS cert ใหม่ให้ตรง IP: `./gen-self-signed-cert.sh 172.16.46.130` (cert เดิมผูกกับ IP เก่า
  จะ mismatch SAN ถ้าไม่ทำ)
- แก้ `.env` บนเซิร์ฟเวอร์: `FRONTEND_URL` / `APP_BASE_URL` → `https://172.16.46.130`
- `docker compose -f docker-compose.prod.yml up --build -d` — build ผ่านทั้ง 3 image, ทุก container
  `healthy`/`running` ปกติ
- Verify: `/api/health` → `{"status":"ok"}`, หน้าแรก 200, `/api/equipment` ไม่มี token → 401, `http://` redirect
  ไป `https://` (301) ถูกต้อง

### Backend/Frontend — แก้บั๊กสร้างชุดอุปกรณ์ไม่ได้เลย (commit `15b1058`)

- **อาการ:** จาก backend log จริงพบ `POST /bundles` ล้มเหลวด้วย `400 Bad Request` ซ้ำหลายครั้งช่วงที่ผู้ใช้ทดลองสร้าง
  "ชุดUnoR3"
- **Root cause:** `bundle_service._replace_items()` บังคับว่าตัวกระตุ้น (`trigger_equipment_id`) ต้องไม่ซ้ำกับ
  สมาชิกในชุด (กันกดยืมแล้วได้ตัวกระตุ้น 2 เท่า) แต่ `frontend/src/pages/admin/BundleManagePage.jsx` เดิม
  ให้เลือกตัวกระตุ้นจาก `<select>` ที่มีตัวเลือกเป็น "ของที่อยู่ในชุดแล้วเท่านั้น" — บังคับให้ trigger ชนกับ item
  เสมอ สร้างชุดที่มีตัวกระตุ้นไม่ได้เลยไม่ว่าจะลองยังไง
- **แก้:** เปลี่ยนช่องเลือกตัวกระตุ้นเป็นช่องค้นหาแยกต่างหาก (เหมือนช่องเพิ่มสมาชิก) ไม่ผูกกับรายการสมาชิก —
  เพิ่ม state `triggerSearch`/`triggerResults`, ฟังก์ชัน `pickTrigger()` ที่ถอดตัวกระตุ้นออกจาก `items` อัตโนมัติ
  ถ้าเคยถูกเพิ่มเป็นสมาชิกไว้ก่อน, `add()` กันไม่ให้เพิ่มตัวกระตุ้นเป็นสมาชิกซ้ำ
- Build (`vite build`) + `npm test` (6 ตัว) ผ่านหมด → commit `15b1058` → push → deploy ขึ้น prod แล้ว
- ทดสอบสร้างชุด "ชุดUnoR3" จริงบนเว็บ prod (ตัวกระตุ้น = Arduino UNO R3, สมาชิก = สายไฟจัมเปอร์ ผู้-ผู้) สำเร็จ —
  ยืนยันใน DB ว่า `trigger_equipment_id` ถูกตั้งค่าถูกต้อง

### แก้ไขข้อมูลบน Production DB

- **เปลี่ยนชื่อ** ครุภัณฑ์ `Arduino-UNO-R3` (42 ชิ้น, รหัส 212001–212042) → `Arduino UNO R3` (มีเว้นวรรค อ่านง่ายขึ้น)
  ทำผ่าน `equipment_service.update_equipment` จริง (ไม่ใช่ SQL ตรง) เพื่อให้มี audit log ครบทุกรายการตามกฎ CLAUDE.md
  ตรวจแล้วไม่ชนชื่อ "บอร์ด Arduino UNO R3" (วัสดุ คนละ item_type) หรือ "Arduino UNO R4 Minima" (คนละรุ่น)

- **พบ+แก้บั๊ก "ยืมหลายชิ้นไม่แยกรายการ" รอบใหม่บน prod (คนละสาเหตุกับที่แก้ไปแล้วใน `800d970`):**
  - ผู้ใช้รายงานว่ายืม Breadboard 830 holes MB-102 (Brd-02) หลายชิ้นแล้วไม่แยกรายการ ตั้งทฤษฎีว่าเกี่ยวกับ
    รูปแบบรหัส (ไม่ได้เริ่มที่ 001)
  - ทดสอบจริงทั้งเรียก `borrow_service.create_request()` ตรง ๆ และผ่านเว็บ (สร้างคำขอยืม Breadboard x4 จริงบน prod
    แล้วปฏิเสธทิ้ง) — พิสูจน์ว่า split logic ทำงาน**ถูกต้อง 100%** ไม่ว่ารหัสจะเป็นรูปแบบไหน (กลุ่มด้วย name+item_type
    เท่านั้น ไม่เกี่ยวกับ `code` เลย) — ทฤษฎีของผู้ใช้ไม่ตรงกับโค้ดจริง
  - **Root cause ที่แท้จริง:** สคริปต์ `split_material_equipment.py` ที่แยกวัสดุก้อนเดียวเป็นรายชิ้น **รันแค่บน DB dev
    เท่านั้น** (ตามที่บันทึกไว้ในรายงานรอบแรกของวันนี้) — DB prod เป็นข้อมูลนำเข้าจากทะเบียนจริงคนละชุด ไม่เคยรัน
    สคริปต์นี้ จึงมีอุปกรณ์วัสดุ 5 รายการค้างเป็นแถวเดียว `quantity_total>1` บน prod:
    `ACC-KEYBOARD-001` คีย์บอร์ด USB (40), `MAT-ARD-001` บอร์ด Arduino UNO R3 (25),
    `MAT-ESP-001` บอร์ด ESP32 DevKit (15), `ACC-PWR-001` สายไฟ AC คอมพิวเตอร์ (40), `ACC-MOUSE-001` เมาส์ USB (40)
  - แยกครบทั้ง 5 รายการผ่านปุ่ม "แยกเป็นรายชิ้น" ในหน้าจัดการอุปกรณ์ (ของจริงบนเว็บ ไม่ใช่ script ตรง DB) — มี
    audit log `split_equipment` บันทึกครบทุกรายการ, ตรวจซ้ำแล้วไม่มีอุปกรณ์ material/durable ที่ยัง
    `quantity_total>1` ค้างอยู่บน prod อีกต่อไป

- **IP เครื่อง VM เปลี่ยนบ่อย** (เปลี่ยนไปแล้ว 2 รอบ: `172.16.46.10` → วันนี้ `172.16.46.130`) — ทุกครั้งที่เปลี่ยนต้อง
  regenerate TLS cert ด้วย ไม่ใช่แค่แก้ `.env` (ไม่งั้น HTTPS จะ error หนักกว่าเดิม เพราะ cert ผูก IP ตรง ๆ)
- **ALLOWED_EMAIL_DOMAINS** ยังไม่ได้ยืนยันกับอาจารย์ว่า domain อีเมลมหาลัยที่ใช้จริงคืออะไร ก่อน deploy จริงเต็มรูปแบบ
  (Pending Item ตาม CLAUDE.md ข้อ 10 — ยังค้างอยู่)
- **ไฟล์ Excel คลังอุปกรณ์เดิม** — ตอนนี้ import เข้าไปแล้วจริงบน prod (707 ครุภัณฑ์ + 617 วัสดุ) แต่ยังต้องเฝ้าดูว่า
  มีรายการ material/durable แถวเดียว `quantity_total>1` หลุดมาอีกไหมถ้ามีการ import เพิ่มรอบใหม่ในอนาคต — ทุกครั้งที่
  import วัสดุจำนวนมาก ให้เช็ค query นี้ซ้ำก่อนปล่อยให้ยืมจริง
