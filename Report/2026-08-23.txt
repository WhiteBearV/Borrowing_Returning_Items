## สิ่งที่ทำสำเร็จวันนี้ ✅

### Backend

**Phase B — 6 ฟีเจอร์จาก feedback ทดลองใช้งานจริง:**
- แก้ไข `code`/`item_type` ของอุปกรณ์ได้หลังสร้างแล้ว — เพิ่มฟิลด์ใน `EquipmentUpdate` (`schemas/equipment.py`),
  `update_equipment()` เพิ่ม dup-check code + audit detail (`code_from/to`, `item_type_from/to`) ใน
  `services/equipment_service.py` — ปลอดภัยกับใบยืมเก่าเพราะ `BorrowItem` เก็บ `item_type_snapshot` แยก
  จาก equipment ตัวจริง ตรวจสอบเพิ่มด้วยการแก้ item_type ขณะมีคำขอยืมอนุมัติค้างอยู่จริง แล้วยืนยันว่า
  ระบบคืนของด้วย condition set เดิมถูกต้อง
- วัสดุสิ้นเปลืองเว้นรหัสว่างได้ — `_generate_consumable_code()` ออกรหัสจากชื่อ+เลขลำดับอัตโนมัติ
  (`{ชื่อ}-001`) ใน `equipment_service.py`, ต่อเข้า `create_equipment()`
- เลือกอุปกรณ์หลายรายการลบถาวร/แก้ไขพร้อมกัน — `bulk_delete_equipment()` (best-effort ต่อรายการ),
  `bulk_update_equipment()` (all-or-nothing) ใน `equipment_service.py`, endpoint
  `POST /equipment/bulk-delete`, `PATCH /equipment/bulk-update` ใน `routers/equipment.py`
- หน้าอนุมัติคำขอรวมคำขอที่แจ้งขอคืนในหน้าเดียว — เพิ่ม param `needs_attention` ใน `list_requests()`
  (`borrow_service.py`) รวม pending + approved ที่มี item แจ้งขอคืนในเควรีเดียว

**ฟีเจอร์เพิ่มเติมจาก feedback รอบถัดมา:**
- status filter ในหน้าจัดการอุปกรณ์ เพิ่ม "สต็อกต่ำ"/"ถูกยืมอยู่" — `_apply_status_filter()` ใหม่ใน
  `equipment_service.py` (mirror สูตร low_stock เดียวกับ `dashboard_service.get_summary`)
- ทำเครื่องหมายแจ้งเตือนว่าอ่านแล้วทั้งหมด — `notification_service.mark_all_read()` +
  `PATCH /notifications/read-all`

**บั๊กที่พบและแก้ระหว่างทาง:**
- `list_equipment_grouped()` filter "ถูกยืมอยู่" ที่ระดับแถวก่อน group ทำให้ยอด "คงเหลือ" ผิด (ตัดหน่วย
  พี่น้องในกลุ่มเดียวกันออกจากยอดรวม เช่น อุปกรณ์มี 42 หน่วยจริง ยืมอยู่แค่ 1 แต่โชว์ "0/1" แทน "41/42") —
  แก้โดยแยก filter ไปทำที่ระดับกลุ่มหลัง group เสร็จแล้ว
- `users_service.delete_user()` ไม่เคลียร์ `approved_by`/`returned_by` FK ก่อนลบ — ลบ admin ที่เคย
  อนุมัติ/รับคืนคำขอของคนอื่นไม่ได้เลย (ชน FK กลายเป็น 500) เจอจากการลบบัญชีทดสอบค้างจริง
- `backend/tests/conftest.py` `_delete_user_cascade()` ลำดับลบ FK ผิด + ไม่เคลียร์ `approved_by`/`returned_by`
  ทำให้ teardown เทสที่มี user คนเดียวกันเป็นทั้งผู้ยืม/ผู้อนุมัติล้มเหลวกลางคัน
