**2. ค้นหาด้วยรหัสอุปกรณ์ (bug)**

**3. ของประจำห้องห้ามยืม (bug + ฟีเจอร์ใหม่)** — ตาม Business Rules ข้อ "การยืมอุปกรณ์"

- ใช้ `status=unavailable` แทนไม่ได้ เพราะ import ทะเบียนรอบหน้าจะเขียนทับ status กลับเป็น available
- `app/models/equipment.py` — เพิ่มคอลัมน์ `is_borrowable: bool` (default true) — import ไม่แตะฟิลด์นี้
- `alembic/versions/0009_equipment_is_borrowable.py` (ใหม่) — migration + backfill ตั้งห้ามยืมให้ 292 ชิ้น
  (โต๊ะ/ตู้/เฟอร์นิเจอร์ 284, โสตทัศนูปกรณ์ 4, ซอฟต์แวร์/ลิขสิทธิ์ 4)
- `app/services/borrow_service.py::create_request` + `approve_request` — บล็อกทั้งตอนยื่นคำขอและตอนอนุมัติ
- แถมแก้อีก bug: เดิมเช็ค `status != available` **เฉพาะ durable** → วัสดุ/วัสดุใช้ซ้ำที่แอดมินตั้งเป็น
  "ไม่อนุญาตให้ยืม"/"ซ่อม" (30 รายการในคลัง) ยังยืมผ่านได้ถ้ามีของเหลือ ตอนนี้บล็อกทุกชนิด
- `app/schemas/equipment.py` — เพิ่ม `is_borrowable` ใน Response/Create/Update

**4. เวลาในเอกสารเพี้ยน 7 ชั่วโมง (bug)**
- ต้นเหตุ: DB เก็บเวลาเป็น UTC แต่ `pdf.py` เอา timestamp มา `strftime` ตรง ๆ → 14:11 กลายเป็น 07:11
- `app/core/config.py` — เพิ่ม `TZ = ZoneInfo("Asia/Bangkok")`
- `app/utils/pdf.py` — เพิ่ม `_local()` แปลงโซนก่อน format ทั้ง `_fmt_date`/`_fmt_datetime` และ `_now()` → `datetime.now(TZ)`
- `app/services/equipment_service.py::build_stock_document` — แก้การตัดช่วงวันที่ (เดิมเทียบ naive date กับ created_at ที่เป็น UTC
  → ของที่ทำก่อน 07:00 น. ตกไปอยู่วันก่อนหน้า) ตอนนี้ตีความช่วงวันตามเวลาไทย

**5. PDF metadata (bug)**
- PDF ไม่มี `/Title` → Chrome แสดงแท็บว่า "(anonymous)"
- `pdf.py::_doc_title()` — ฝังชื่อเอกสารลงไฟล์ เช่น "ใบยืมสิ่งของและอุปกรณ์ REQ-2026-6610301006-b511af"

**6. นำเข้าคลังจากรูปถ่าย/PDF ด้วย OCR (ฟีเจอร์ใหม่ — โหมดทดลอง)**
- `app/services/ocr_import.py` (ใหม่) — Tesseract (`tha+eng`) + poppler แปลง PDF เป็นรูป 300dpi
  `parse_line()` แยกบรรทัดด้วย regex: รหัสต้นบรรทัด + ชื่อ + จำนวน/หน่วยท้ายบรรทัด
  บรรทัดที่ไม่มีรหัสนำ (หัวตาราง) เข้ากอง "ข้าม" พร้อมเหตุผล
- `app/services/import_service.py` — `_parse_file()` เลือกตัวอ่านตามนามสกุล, `_import_path()` หาไฟล์ตอน commit
  → `POST /equipment/import/preview` รับ .jpg/.png/.pdf เพิ่มจาก .xlsx **ไหลเข้าหน้าร่างนำเข้าเดิมทั้งหมด**
  (แอดมินตรวจ/แก้/ตัดออกทุกแถวก่อนบันทึก → OCR อ่านผิดไม่หลุดเข้า DB, commit ยังอ่านไฟล์ซ้ำกันยัด payload)
- เหตุผลที่เลือก Tesseract: ไม่ผูกกับบัญชี/เครดิตของใคร ไม่ต้องต่อเน็ต ข้อมูลทะเบียนไม่ออกนอกเซิร์ฟเวอร์
  **โน้ตไว้ในหัวไฟล์ว่าถ้าแม่นไม่พอให้เปลี่ยนแค่ `_ocr_text()` ไปเรียก vision API** ที่เหลือใช้ต่อได้หมด
- ทดสอบจริง: รูปสังเคราะห์ 4 แถว อ่านครบ จำนวน/หน่วย/หมวดถูกหมด แต่ "KidBright 32i" ตกตัว i
  (นี่คือรูปคมชัดที่สุดเท่าที่เป็นไปได้ — รูปถ่ายจริงจะแย่กว่านี้)

**7. เอกสาร PDF ให้ตรงแบบฟอร์มจริงของคณะ** (จากไฟล์ตัวอย่างที่ได้รับวันนี้)
- `pdf.py::_build_borrow_form()` (เขียนใหม่) — **ใบยืม** ตามฟอร์ม "ใบยืมสิ่งของและอุปกรณ์" ของคณะ:
  หัวเรื่อง 2 บรรทัด, วันที่ไทย พ.ศ., ข้าพเจ้า/ตำแหน่ง/ฝ่ายงาน, ตาราง ลำดับ·รายการ·จำนวน·รหัสครุภัณฑ์
  (เว้นบรรทัดว่างเผื่อเขียนมือ), ย่อหน้ารับรองคำต่อคำ, ลายเซ็น 4 ช่อง (ผู้รับของ/ผู้ส่งของ/ผู้ส่งของคืน/ผู้รับคืน)
  * ตำแหน่งเดาจากการมีรหัสนักศึกษา (นักศึกษา / อาจารย์-เจ้าหน้าที่) → ไม่ต้องเพิ่มฟิลด์ใน DB
- `pdf.py::generate_repair_pdf()` (ใหม่) — **ใบขออนุมัติซ่อมแซมครุภัณฑ์** (บันทึกข้อความ ตามฟอร์ม พศ.004:1)
  ตารางดึงครุภัณฑ์ที่ status ∈ {damaged, under_repair} และ **ช่อง "ลักษณะ/สภาพที่ชำรุด" ดึงจาก `damage_note`
  ตอนแอดมินรับคืน** ไม่ต้องพิมพ์ซ้ำ
  + `equipment_service.build_repair_document()` + `GET /equipment/repair-document` (admin)
- `pdf.py::_build_receipt_form()` (ใหม่) — **ใบรับเข้าคลัง** เปลี่ยนเป็น "รายการเบิกครุภัณฑ์" ตามใบจริง:
  หัวสถาบัน, เลขที่ใบเบิก/อ้างอิงใบตรวจรับ, ชื่อ-สกุล/ตำแหน่ง/หน่วยงาน,
  ตาราง ลำดับ·รายการ·จำนวน·ราคาต่อหน่วย·จำนวนเงิน·**รหัสครุภัณฑ์รายชิ้น**, ลายเซ็นผู้เบิก/ผู้จ่าย
- หมายเหตุ: กล่องเช็ก ☐ ใช้ไม่ได้ (ฟอนต์ Garuda ไม่มี glyph) เปลี่ยนเป็น `[ ]`

## ปัญหาที่พบ / ปัญหาที่ยังค้างอยู่ 🔴

| ปัญหา | สาเหตุ | วิธีแก้ / แผน |
|---|---|---|
| OCR อ่านชื่อรุ่นตกตัวอักษร ("KidBright 32i" → "32") | Tesseract แม่นจำกัด แม้กับรูปคมชัด | ต้องทดสอบกับ**รูปถ่ายทะเบียนจริง** ถ้าต้องแก้เกินครึ่ง = สลับ `_ocr_text()` ไป vision API (Gemini free tier / Anthropic) |
| Vision API ต้องผูกกับบัญชีของใครสักคน + ข้อมูลออกนอกเซิร์ฟเวอร์ | เป็นบริการภายนอกทั้งหมด | ถ้าจะใช้จริงหลังส่งมอบ ต้องขอ key จากคณะ ไม่ใช่บัญชีส่วนตัว + ขออนุญาตเรื่องทะเบียนครุภัณฑ์ราชการก่อน |
| ใบเอกสารราชการมีช่องที่ระบบเติมไม่ได้ (ราคา/วงเงิน/เลขสัญญา/กรรมการ) | ระบบคลังไม่มีข้อมูลฝั่งจัดซื้อ | เว้นว่างให้กรอกมือ — จะเติมอัตโนมัติต้องเก็บ `unit_price` ตอนนำเข้า = กลายเป็นระบบจัดซื้อ (นอกขอบเขต) |
| ใบปลดระวาง (ร่างออก) ยังเป็นดีไซน์ของระบบเอง | ยังไม่ได้รับฟอร์มจริงจากคณะ | ขอไฟล์ตัวอย่างจากอาจารย์ แล้วทำแบบเดียวกับอีก 3 ใบ |
| ใบรับคืนยังแยกเป็นอีกใบ | ฟอร์มกระดาษจริงใช้ใบยืมใบเดียวเซ็นทั้งยืมและคืน | รอตัดสินใจ: จะเลิกออกใบรับคืนแยก หรือเก็บไว้เป็นสรุปสภาพ |
| งานทั้งหมดวันนี้ยังไม่ commit | สะสมหลายเรื่อง | commit แยกเป็นก้อน ๆ (หมวดวัสดุ / ห้ามยืม / timezone / OCR / เอกสาร) |
