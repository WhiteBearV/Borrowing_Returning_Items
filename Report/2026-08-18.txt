### เนื้อหาวันนี้: แก้ 4 feedback จากผู้ใช้จริง + QA ครบวงจรทั้งระบบ

รับ feedback จากการทดลองใช้จริง 4 ข้อ: (1) dashboard อุปกรณ์ไม่ลดลงหลังอนุมัติ + อยากเห็นจำนวนที่ถูกยืมอยู่ (2) อยากให้หน้าจัดการอุปกรณ์ยุบครุภัณฑ์รุ่นเดียวกันเหมือนหน้ายืมของนักศึกษา (3) ยืม "ชุด UnoR3" ได้ Uno ซ้ำ 2 ชิ้นแทนที่จะได้ Uno+สาย USB-C (4) ช่องสถานที่เก็บใส่รายละเอียดเพิ่ม (เช่น "15312 ตู้A ชั้น3") ไม่ได้ หลังแก้เสร็จทำ QA ครบวงจรทั้งระบบ (backend pytest + browser จริง) พบบั๊กเพิ่มอีก 2 ข้อระหว่างทดสอบ และพบว่าปัญหาชุดอุปกรณ์ยืมซ้ำเป็นปัญหาเชิงระบบ ไม่ใช่แค่ชุดเดียว — แก้ครบทั้งหมดแล้ว

### Backend

**Dashboard — สถิติ "อุปกรณ์ที่ถูกยืมอยู่"**
- `backend/app/schemas/dashboard.py` — เพิ่ม field `equipment_borrowed_out: int` ใน `DashboardSummaryResponse`
- `backend/app/services/dashboard_service.py::get_summary` — เพิ่ม query นับจำนวนอุปกรณ์ที่ถูกยืมอยู่จริง
  - **รอบแรกใช้สูตรผิด** (`quantity_total - quantity_available`) ซึ่งรวมของชำรุด/ซ่อมอยู่/แอดมินปิดใช้งานเองด้วย ไม่ใช่แค่ของที่ถูกยืมจริง — เจอตอน QA จริง (เลขขึ้น 55 ทั้งที่คำขอ approved = 0) แก้เป็น join `BorrowItem`+`BorrowRequest` นับเฉพาะ `status=approved AND returned=false` แทน ยืนยันผ่าน browser จริงว่าอนุมัติ→เลขขึ้น, คืนแล้ว→เลขกลับ 0

**หน้าจัดการอุปกรณ์ — ยุบครุภัณฑ์รุ่นเดียวกัน**
- `backend/app/schemas/equipment.py` — เพิ่ม `EquipmentUnitSummary` (id/code/status/quantity/is_borrowable ต่อหน่วย), เพิ่ม field `members` ใน `EquipmentGroupDetailResponse`
- `backend/app/services/equipment_service.py::get_equipment_group_detail` — คืนรายชื่อหน่วยสมาชิกทุกหน่วยในกลุ่ม (ให้หน้าเว็บกางดู/แก้ไข/ปลดระวางรายหน่วยได้) — endpoint `/equipment/grouped` เดิมมีอยู่แล้วจากงาน 17 ส.ค. แค่ต้องเติม `members` list
- `backend/app/services/equipment_service.py::find_group_members` — **บั๊กที่เจอตอน QA:** ไม่ eager-load `categories` → ถ้าเรียกกลุ่มด้วย id ที่ไม่ใช่หน่วยรหัสต่ำสุด จะพัง 500 (`MissingGreenlet` — lazy-load นอก async context) แก้เพิ่ม `.options(selectinload(Equipment.categories))`

**บั๊กชุดอุปกรณ์ยืมซ้ำ (Bundle) — แก้ทั้ง code guard และ ข้อมูลจริง**
- `backend/app/services/bundle_service.py::_replace_items` — เพิ่ม guard: ถ้า `equipment_id` ของ item ตรงกับ `trigger_equipment_id` ของชุดตัวเอง คืน 400 ทันที กันไม่ให้ตั้งค่าผิดซ้ำได้อีก
- **ตรวจ DB จริงพบว่าทุกชุดที่มีอยู่ (3 ชุด: ชุดUnoR3, Pi 4, Dell Optiplex 7040) มีบั๊กแบบเดียวกันหมด** — ตัวกระตุ้นถูกใส่ซ้ำเป็นสมาชิกชุดตัวเอง และชุด UnoR3 ยังตั้งตัวกระตุ้นผิดตัว (เป็น Arduino Mega แทน Uno) แก้ข้อมูลจริงผ่านหน้าเว็บครบทั้ง 3 ชุดแล้ว (ชุดUnoR3 → เปลี่ยนตัวกระตุ้นเป็น Arduino-UNO-R3 ตัวจริง; Pi4/Dell → ลบตัวเองออกจากรายการของพ่วงตัวเอง)

### Frontend

- `frontend/src/pages/admin/DashboardPage.jsx` — เพิ่ม stat card "อุปกรณ์ที่ถูกยืมอยู่" ต่อจาก "คำขอที่ยืมอยู่"
- `frontend/src/pages/admin/EquipmentManagePage.jsx` (ไฟล์ที่แก้เยอะสุดวันนี้)
  - เปลี่ยน `load()` จาก `equipmentApi.list` → `equipmentApi.listGrouped` — ตารางยุบครุภัณฑ์รุ่นเดียวกันเป็นแถวเดียวพร้อม badge จำนวนหน่วย
  - เพิ่ม state `expanded` + `toggleExpand`/`refreshExpanded`/`editMember` — กางดูรายหน่วยในกลุ่ม แก้ไข/ปลดระวางทีละหน่วยได้โดยไม่กระทบหน่วยอื่น
  - แก้ `toggleBundleTrigger` ให้เคลียร์ "รวมในชุด" อัตโนมัติเมื่อติ๊ก "ตัวกระตุ้น" (เดิมทำได้แค่ทางเดียว — ติ๊ก "รวมในชุด" เคลียร์ตัวกระตุ้น แต่ทางกลับไม่เคลียร์)
  - เพิ่ม placeholder ช่องสถานที่เก็บ: "เช่น 15312 ตู้A ชั้น3 (ไม่บังคับ)" — field เดิมเป็น free-text อยู่แล้วทั้ง backend/schema ไม่ต้องแก้อะไรนอกจาก UI hint
- `frontend/src/hooks/useBorrowCart.js::addBundle` — เพิ่ม defensive filter กัน equipment ที่เป็นตัวกระตุ้นถูกเพิ่มซ้ำเข้าตะกร้าอีกรอบ เผื่อข้อมูลชุดเก่าที่ยังพังอยู่ในฐาน (ชั้นป้องกันที่ 2 นอกจาก backend guard)
