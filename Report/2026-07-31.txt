**ช่องว่างที่เจอ (backend มีแล้วแต่ frontend เข้าไม่ถึง):**
- แจ้งเตือนในระบบ (`GET /notifications/me`) — backend สร้าง record จริง แต่ไม่มี component ไหนเรียกเลย
- ลืมรหัสผ่าน (`/auth/forgot-password`, `/auth/reset-password`) — `LoginPage.jsx` มีลิงก์ไปหน้าที่ไม่มีจริง (404)
- ปุ่ม remind แบบ manual, QR code อุปกรณ์ — มี API client แล้วแต่ไม่มีปุ่มเรียกใช้ (ยังไม่ได้แก้รอบนี้)
- `notification_service.send_notification()` เป็น dead code, ช่อง email/line ใน service นี้เป็นแค่ TODO ค้าง

**ช่องว่างเชิงความปลอดภัย/best practice (ยังไม่ได้แก้รอบนี้):** ไม่มี rate limit บน `/auth/login`,
ไม่มี password policy, ไม่มี CI, `.env` ยัง `DEV_AUTO_VERIFY_EMAIL=true`, ไฟล์รูปกำพร้าใน `/uploads`

### Backend
- **`borrow_service.py::create_request`** — เพิ่มอีเมลแจ้ง admin ทุกคนเมื่อมีคำขอใหม่ (นอกเหนือจาก
  in-app เดิม) ยกเว้นตัวเองถ้า admin ยืมของตัวเอง (self-borrow) ไม่ให้ได้แจ้งเตือน "มีคำขอใหม่" ซ้ำกับ
  คำขอที่ตัวเองเพิ่งส่ง — เจอบั๊กนี้จากทดสอบจริงด้วยบัญชี `6610301006@cdti.ac.th` ที่ผู้ใช้ตั้งเป็น admin
  แล้วยืมของเอง เห็นแจ้งเตือนแบบ admin ปนกับแบบผู้ยืมของคำขอเดียวกัน
- **`scheduler.py::_check_overdue`** — เพิ่มอีเมล digest เดียวต่อรอบให้ admin ทุกคนเมื่อมีรายการเกิน
  กำหนดคืน (กันสแปมถ้าเกินพร้อมกันหลายรายการ)
- **security fix** (จาก background security review) — `escape()` (stdlib `html`) ชื่อผู้ใช้/เลขคำขอก่อน
  ฝัง HTML ในอีเมล admin ทั้ง 2 จุดข้างบน `full_name` มาจากผู้ใช้กรอกตอนสมัคร ไม่ escape จะเปิดช่อง
  HTML injection ในอีเมล
- ตรวจสาเหตุที่อีเมลไม่ถึงจริงตอนผู้ใช้ทดสอบ: `.env` ยัง `MAIL_USERNAME=your-email@example.com`
  (placeholder) → `_email_configured=False` → `SUPPRESS_SEND=True` ระบบ print แทนส่งจริงเสมอ ไม่ใช่บั๊ก
  โค้ด แต่ยังไม่ได้ตั้งค่า SMTP จริง (verify ด้วยการรัน python import `app.utils.email` ตรง ๆ)

## ปัญหาที่พบ / ปัญหาที่ยังค้างอยู่ 🔴

| ปัญหา | สาเหตุ | วิธีแก้ / แผน |
|---|---|---|
| อีเมลไม่ถึงจริงตอนทดสอบ | `.env` ยังเป็น placeholder Gmail credential | ต้องกรอก MAIL_USERNAME/MAIL_PASSWORD (Gmail App Password) จริง แล้ว restart backend |
| แจ้งเตือน admin ปนกับ user เมื่อบัญชีเดียวเป็นทั้งสองบทบาท | admin ที่ยืมของตัวเองโดน notify ซ้ำ | แก้แล้ววันนี้ — ข้าม self ในลูปแจ้งเตือน |
| ปุ่ม remind แบบ manual + QR code ไม่มีทางเข้าจาก UI | มี backend/API client แต่ไม่มี component เรียก | ยังไม่ได้ทำรอบนี้ — รอคิว |
| password policy ไม่มี | schema `password: str` ไม่บังคับความยาว/ความซับซ้อน | ยังไม่ได้ทำ — ต้องคุยกับผู้ใช้ก่อนว่าจะบังคับระดับไหน |
| `DEV_AUTO_VERIFY_EMAIL=true` ยังเปิดใน `.env` | ตั้งไว้ตอน dev | ต้องปิดก่อน deploy production |

## สถานะโดยรวม

**Backend:** ~99% ของ MVP+feedback ทั้งหมด — ฟีเจอร์ตามบันทึกปรึกษาปิดครบ เหลือ hardening

remind/QR ที่ยังไม่มีปุ่มเรียก
**ระยะรวม:** ใกล้พร้อม deploy — เหลืองาน hardening ด้านความปลอดภัยและตั้งค่า SMTP จริงเป็นด่านสุดท้าย
