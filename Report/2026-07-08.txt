- **[advisor #8] Audit log ใช้งานได้จริง** — เดิม `audit_service.log_action()` ไม่เคยถูกเรียก
  (audit_logs ว่างตลอด) เสียบเข้า approve/reject/return (borrow_service.py) และ
  create/update/retire/delete equipment (equipment_service.py + routers/equipment.py thread admin)

- **[advisor #7] แก้เลขคำขอชนกัน** — เดิม `_next_request_code` ใช้ count+1 (race ได้ → ชน
  unique constraint 500) เปลี่ยนเป็น `_build_request_code` = REQ-{ปี}-{student_id}-{hex6 จาก
  uuid คำขอ} (borrow_service.py, models/borrow_request.py ขยาย 30→40, migration 0006)
- **[#3] วัสดุสิ้นเปลือง 3 สถานะ** — แก้บั๊ก approve แล้วขึ้น "คืนแล้ว" ผิด
  approve_request เลิก auto-mark consumable returned; return_item รับสถานะ
  returned_full/used_up/discarded (คืนสต็อกเฉพาะ ok/returned_full); return_all_items
  รับคืนเฉพาะ durable, completed เมื่อทุก item สรุปครบ (borrow_service.py)
  *แก้ Business Rule ใน CLAUDE.md หัวข้อ 5 (การอนุมัติ/การคืน) ให้ตรงพฤติกรรมใหม่*
- **[#1] บังคับรูปความเสียหาย** — condition damaged/lost/discarded ต้องแนบ
  damage_photo_urls ≥1 รูป (schemas/borrow.py + borrow_service.py)
- **[#2] รูปโปรไฟล์ผู้ใช้** — users.avatar_url (migration 0007) + POST /users/me/avatar
  (users_service.update_avatar reuse equipment_service.save_image), routers/users.py
- **[security] Audit trail แก้ไม่ได้** — จาก security review พบว่า delete_user เดิม
  hard-delete audit_logs ของ actor (admin ลบบัญชีเพื่อลบร่องรอยตัวเองได้ = tampering)
  แก้: snapshot actor_name/identifier ตอนเขียน log, FK actor_id เป็น ON DELETE SET NULL
  (migration 0008), delete_user เลิกลบ audit_logs
