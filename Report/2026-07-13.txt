### 2. Backend — ฟีเจอร์นำเข้าจาก Excel (ไฟล์ใหม่/แก้ไข)

- **`app/services/import_service.py` (ใหม่, ~230 บรรทัด)**
  - `parse_workbook()` — อ่านไฟล์ทะเบียนคุมทรัพย์สิน 3 ชีต:
    "คณะเทคโนฯดิจิทัล" (เลขครุภัณฑ์ปกติ), "ครุภัณฑ์ที่ได้รับพระราชทาน" (ใช้รหัสใหม่ สนว.-),
    และ **"วัสดุ" (ชีตใหม่ที่ออกแบบเอง)** สำหรับวัสดุที่ไม่มีเลขในทะเบียน —
    คอลัมน์: รหัส | รายการ | ประเภท | หน่วยนับ | จำนวน | สถานที่จัดเก็บ
    แปลงคอลัมน์ ปกติ/ชำรุด/เสื่อมสภาพ/สูญหาย → `status` + `quantity_available` (ใช้กฎเดียวกับ
    `scripts/import_register.py` ที่ seed ครั้งแรก) และจัดหมวดอัตโนมัติจากคีย์เวิร์ดในชื่อ
  - `diff_rows()` — เทียบไฟล์กับ DB คืน action รายบรรทัด: `new` / `update` / `unchanged` / `retire`
    (retire = ครุภัณฑ์ที่มีใน DB แต่หายไปจากไฟล์ — วัสดุไม่ถูก flag เพราะไม่ได้อยู่ในทะเบียนอยู่แล้ว)
    เทียบจำนวน (`quantity_total`) เฉพาะวัสดุ เพราะครุภัณฑ์ 1 เลขทะเบียน = 1 ชิ้นเสมอ
  - `preview_import()` — เก็บไฟล์ไว้ที่ `uploads/imports/<uuid>.xlsx` แล้วคืนร่าง (ยังไม่แตะ DB)
  - `commit_import()` — รับ "ร่างที่แอดมินตรวจ/แก้แล้ว" มาบันทึกเฉพาะบรรทัดที่ส่งมา
    เขียน audit log ทุกบรรทัดด้วย action เดิม (`create_equipment` / `update_equipment` /
    `retire_equipment`) → ออกใบรับเข้าคลัง/ใบปลดระวาง PDF ต่อได้ทันทีโดยไม่ต้องเขียนโค้ดเพิ่ม
- **`app/routers/equipment.py`** — เพิ่ม 2 endpoint (admin only):
  `POST /equipment/import/preview` (multipart upload) และ `POST /equipment/import/{import_id}/commit`
- **`app/schemas/equipment.py`** — เพิ่ม `ImportRowIn` / `ImportCommitRequest`
  (code, action, name, location, status, item_type, quantity, unit, categories, description,
  image_urls, reason)
- **`app/core/config.py`** — แก้ `env_file` ให้เป็น absolute path ของ `backend/.env`
  (เดิมเป็น relative → รันสคริปต์จากโฟลเดอร์ `scripts/` แล้วพัง เพราะหา .env ไม่เจอ)
- **`requirements.txt`** — เพิ่ม `openpyxl>=3.1.0`

**ความปลอดภัย:** commit ไม่เชื่อ payload จาก browser ดื้อ ๆ — เซิร์ฟเวอร์อ่านไฟล์ต้นทางซ้ำ
แล้วตรวจว่าทุกบรรทัดที่ส่งมามีอยู่ในไฟล์จริงและ action ตรงกับที่ระบบคำนวณ (ไม่งั้น 400)
ส่วนค่า ชื่อ/สถานะ/หมวด/รูป ใช้ตามที่แอดมินแก้ในร่าง

### 3. Frontend — ปุ่ม "นำเข้าจาก Excel" + หน้าร่างเอกสาร

- **`pages/admin/EquipmentManagePage.jsx`** — เพิ่ม `ImportModal` ทำงาน 3 จังหวะ:
  1. อัปโหลดไฟล์ → ระบบอ่าน
  2. **สรุปว่าไฟล์เปลี่ยนอะไร** (เพิ่มใหม่ / อัปเดต / ไม่พบในไฟล์ / ไม่เปลี่ยน + รายการที่ข้ามเพราะไม่มีรหัส)
  3. **"ร่างเอกสารปรับปรุงคลัง — ตรวจก่อนบันทึก"** ← ตัวหลัก มีหัวเอกสาร (วันที่ · ผู้ทำรายการ ·
     ที่มา = ชื่อไฟล์) และคอลัมน์ **"log ที่จะลงระบบ"** บอกว่าแต่ละบรรทัดจะเขียน audit log ว่าอะไร
     - ติ๊กออก = ไม่บันทึกบรรทัดนั้น (retire ไม่ติ๊กมาให้ ต้องติ๊กเอง)
     - แก้ในตาราง: ชื่อ / ประเภท (ครุภัณฑ์-วัสดุใช้ซ้ำ-วัสดุสิ้นเปลือง) / จำนวน / สถานที่ / สถานะ / เหตุผลปลดระวาง
     - กด "แก้ไข ▾" กางแผงเพิ่ม: **หมวดหมู่ (หลายหมวด) · คำอธิบาย · หน่วยนับ · อัปโหลดรูปหลายรูป**
       → แก้ได้ครบเท่าฟอร์มเพิ่มอุปกรณ์ทีละชิ้น
     - แถว update ที่เว้นว่าง = ไม่แตะข้อมูลเดิมใน DB (ไม่เลือกหมวด = ใช้หมวดเดิม, ไม่อัปรูป = ใช้รูปเดิม)
- **`api/equipmentApi.js`** — เพิ่ม `importPreview(file)` / `importCommit(importId, body)`

### 6. (รอบเย็น) เก็บบั๊กจากการลองใช้งานจริง — ใบร่างยืม + ตะกร้า + ฝั่งแอดมิน

**6.1 ใบร่างยืม (PDF) แสดงข้อมูลผิด/ไม่ครบ** — เจอตอนกดดูใบร่างจากหน้าตะกร้า
- `app/utils/pdf.py` `_build_doc()`:
  - เพิ่มคอลัมน์ **"รหัสอุปกรณ์"** ในตารางรายการ (เลขครุภัณฑ์/รหัสวัสดุจริง) — เดิมมีแต่ชื่อ
    เอกสารเลยเช็คของกับทะเบียนไม่ได้
  - **ตัดคอลัมน์ "สภาพเมื่อคืน" ออกจากใบยืม/ใบร่าง** เหลือเฉพาะใบรับคืนที่มีค่าจริง
    (เดิมโชว์เป็นขีด "-" ทุกแถว ไม่มีความหมาย)
  - **วันกำหนดคืนคำนวณให้แล้ว** = วันที่ยื่น + `max_loan_days_durable` จากตาราง settings
    (ไม่ hardcode) ป้ายกำกับว่า "(ประมาณการ)" เพราะกำหนดคืนจริงนับจากวันอนุมัติ — เดิมโชว์ "-"
  - **รหัสคำขอโชว์รูปแบบจริงเป็นตัวอย่าง** `REQ-2026-6610301002-a1b2c3 (ตัวอย่าง — เลขจริงออก
    เมื่อส่งคำขอ)` โดยเรียก `_build_request_code()` ตัวเดียวกับของจริง — เดิมเขียนแค่ "(ร่าง)"
- `app/models/borrow_item.py` — เพิ่ม property `equipment_code`
- `app/schemas/borrow.py` — `BorrowItemResponse.equipment_code`
- `app/services/borrow_service.py` `generate_preview_pdf()` — เติม code + วันกำหนดคืนประมาณการ

**6.2 แอดมินต้องดูใบร่างฉบับเดียวกับที่นักศึกษาส่งมา**
- `borrow_service.generate_pdf()` — ถ้าคำขอยัง `pending` ให้ออกเป็น **ใบร่าง** (เทมเพลตเดียวกับ
  ที่นักศึกษาเห็นตอนกดพรีวิว) ต่างแค่มีเลขคำขอจริงแล้ว; อนุมัติแล้วค่อยเป็นใบยืมจริง
  → ไม่ต้องเพิ่ม endpoint ใหม่ ใช้ `GET /borrow-requests/{id}/pdf` เดิม (admin เข้าได้อยู่แล้ว)
- `pages/admin/BorrowRequestsPage.jsx` — ปุ่ม **"ดูใบร่าง PDF"** ในหน้าคำขอรออนุมัติ (เปิดแท็บใหม่)
  + โชว์รหัสอุปกรณ์ในลิสต์รายการให้ตรงกับในเอกสาร
- ทดสอบจริง: ล็อกอิน admin → ดึงคำขอ pending จริงจาก DB → ได้ใบร่างพร้อมเลข
  `REQ-2026-6610301002-d1f647` และวันกำหนดคืน 20/07/2026 ถูกต้อง

**6.3 ตะกร้ายืมหายหมดเมื่อกดรีเฟรชหน้า**
- สาเหตุ: `useBorrowCart` เก็บตะกร้าใน `useState` เฉย ๆ → state หายทุกครั้งที่ reload
- `hooks/useBorrowCart.js` — persist ลง `localStorage['borrowCart']` (อ่านตอน init + เขียนทุกครั้ง
  ที่ตะกร้าเปลี่ยน)
- `context/AuthContext.jsx` `logout()` + `context/CartContext.jsx` — ล้างตะกร้าตอนออกจากระบบ
  ทั้ง localStorage และ state ในหน่วยความจำ กันตะกร้าคนก่อนค้างข้ามบัญชีบนเครื่องเดียวกัน
