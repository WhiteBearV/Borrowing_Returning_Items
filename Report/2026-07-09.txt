### Backend

**[ประเด็น 4] แก้เลขครุภัณฑ์ให้ตรงทะเบียนคุมทรัพย์สินจริง**
- เดิม seed มาจาก Snipe-IT ใช้เลข internal (`111001`) ไม่ตรงเลขทางการ — ยืนยันแล้วว่าจริง
- เขียน `backend/scripts/import_register.py` อ่านไฟล์ทะเบียน Excel (2 ชีต) เป็น source of truth
  gen `seed_equipment.sql` ใหม่ 704 ครุภัณฑ์เลขจริง (คณะ `63-/64-/65-/66-/67-...`,
  พระราชทานใช้รหัสใหม่ `สนว.-...` ตามที่อาจารย์สั่ง) จัดหมวดตามคีย์เวิร์ดในชื่อ
  UUID เสถียรด้วย uuid5 (re-seed ซ้ำได้) — ต้องใส่ `image_urls='[]'` เพราะคอลัมน์ NOT NULL
- `reclassify_consumable.sql` + `remap_durable_codes.sql` + `reclassify_material.sql`:
  ล้างข้อมูลยืมทดสอบเก่า (อ้างถึงเลขเก่า, FK NO ACTION ต้องลบตามลำดับ notifications→items→requests)
  ลบ durable Snipe-IT ที่จับคู่ทะเบียนได้ แล้วโหลด 704 ตัวจากทะเบียน (ในทรานแซกชันเดียว)
- ทุกสคริปต์ dry-run ด้วย BEGIN...ROLLBACK ผ่าน `psql -v ON_ERROR_STOP=1` ก่อนลงจริง

**[ตามคำสั่งเจ้าของ] เพิ่ม item_type ที่ 3 = `material` (วัสดุใช้ซ้ำ)**
- เดิมมีแค่ durable/consumable — ตีวัสดุทุกอันเป็นสิ้นเปลืองไม่ถูก
- แยกเป็น 3: `durable` ครุภัณฑ์ / `material` วัสดุใช้ซ้ำ (บอร์ด/คิต/Pi/Arduino) / `consumable`
  วัสดุสิ้นเปลือง (เหลือแค่ ตะกั่ว/สายไฟ/paste)
- `material` ยืมแบบจำนวน (เหมือน consumable) แต่คืนแบบ durable (ok/damaged/lost) —
  logic เดิม `borrow_service.py:345` (`CONSUMABLE_CONDITIONS if =="consumable" else DURABLE`)
  รองรับเองไม่ต้องแก้ return flow
- อัปเดต comment `models/equipment.py`, `utils/pdf.py` (label 3 แบบ), CLAUDE.md หัวข้อ 5

**[ประเด็น 3] เอกสาร PDF — ร่างยืม preview + ร่างคืน**
- refactor `utils/pdf.py` เป็น `_build_doc(req, kind)` ตัวเดียว รองรับ borrow/preview/return
  (ต่างแค่หัวเรื่อง/สีเส้นคาด/ป้ายลายเซ็น) — ไม่เขียน PDF ซ้ำ 3 ชุด
- `_condition_th` เพิ่มสถานะวัสดุสิ้นเปลือง (คืนครบ/ใช้หมด/ทิ้ง)
- `borrow_service.generate_return_pdf` + `generate_preview_pdf` (preview ประกอบ object จากตะกร้า
  ไม่บันทึก DB)
- `routers/borrow.py`: `GET /{id}/return-pdf` + `POST /preview-pdf`
