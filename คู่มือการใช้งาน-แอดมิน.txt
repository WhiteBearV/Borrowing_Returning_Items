1. ฝั่งนักศึกษา

บัญชี
- สมัครเอง → กรอกชื่อ/รหัสนักศึกษา/สาขา/เบอร์โทร + ยินยอม PDPA (ฟิลด์ใหม่ ยังไม่ commit) → ยืนยันอีเมล → login
- จำกัด domain อีเมลตาม ALLOWED_EMAIL_DOMAINS, บังคับ format รหัสนักศึกษา
- ลืมรหัสผ่าน → ส่งลิงก์รีเซ็ตทางอีเมล
- แก้โปรไฟล์ + อัปโหลดรูปโปรไฟล์
- login แล้ว redirect ตาม role อัตโนมัติ

ยืมของ
- ดูร
- ชุดอุปกรณ์ (bundle): หยิบ "คอมพิวเตอร์ตั้งโต๊ะ" ลงตะกร้า → พ่วงเมาส์/คีย์บอร์ด/จอ อัตโนมัติ ถอดออกเองได้
- ดูสถานะคำขอ / ประวัติการยืม / ยกเลิกคำขอที่ยัง pending
- ขอต่อเวลา — เลือกวันที่ใหม่ + เหตุผล ส่งเป็นคำขอ (แอดมินอนุมัติ) เห็นเหตุผลตอนถูกปฏิเสธด้วย
- แจ้งขอคืน — กดแจ้งว่าจะเอาของมาคืน (เป็นแค่ป้ายบอกแอดมิน ไม่ตัดสต็อกเอง)
- โหลด PDF ใบยืมของตัวเอง, กระดิ่งแจ้งเตือนในแอป

2. ฝั่งแอดมิน

จัดการคลัง (หน้าใหญ่สุด 1,581 บรรทัด)
- เพิ่ม/แก้/ปลดระวาง/ลบถาวร, ออกรหัสวัสดุสิ้นเปลืองอัตโนมัติ, validate เลขครุภัณฑ์ตามฟอร์แมตทะเบียนจริง
- อัปโหลดรูปหลายรูปต่อชิ้น, ผูกได้หลายหมวดพร้อมกัน
- แยกเป็นรายชิ้น (split) — แถวเดียว 40 ตัว → 40 ยูนิตพร้อมรหัสรัน
- เติมสต็อก (restock) / ปรับยอดคงเหลือ (adjust-stock) พร้อมเหตุผลลง audit
- Bulk: แก้/ปลดระวาง/ลบ/ปรับยอด หลายชิ้นพร้อมกัน
- QR Code ต่อชิ้น — ฝัง host ตามเครื่องที่เปิดหน้าอยู่ (สแกนจากมือถือใน LAN ได้)
- ธง is_borrowable แยกจาก status — ของประจำห้อง (โต๊ะ/ทีวี) อยู่ในทะเบียนแต่ยืมไม่ได้
- 3 ประเภทของ: durable (ครุภัณฑ์) / material (วัสดุใช้ซ้ำ) / consumable (สิ้นเปลือง) — คนละกติกาการคืน

- แอดมินยืมเองได้ และมีหน้า "คำขอของฉัน" แยกจากหน้าดูของทุกคน
- รับคืนทีละชิ้น ระบุสภาพ + บังคับแนบรูปถ้าชำรุด/สูญหาย, หรือ "รับคืนครุภัณฑ์ทั้งหมด" รวดเดียว
- อนุมัติ/ปฏิเสธคำขอต่อเวลา, ส่งเตือนแบบ manual, ลบคำขอ

เอกสาร PDF (ReportLab, ฟอนต์ไทย)
1. ใบยืม 2. ใบรับคืน (สะสม + เวลาคืน) 3. พรีวิวใบยืมก่อนยื่น 4. บันทึกขออนุมัติซ่อมแซมครุภัณฑ์ (ของชำรุด/ซ่อมอยู่ทั้งหมด) 5. ใบรับเข้าคลัง / ใบปลดระวาง ตามช่วงวันที่

อื่น ๆ
- ผู้ใช้: ดู/สร้าง/ระงับ/ลบบัญชี (ลบแล้ว audit log ยังอยู่ — snapshot ชื่อผู้ทำไว้)
- Audit Log: ทุก action ของแอดมิน (approve, reject, return, create/update/retire/delete equipment, adjust stock, bundle...) พร้อม diff ก่อน-หลัง กรองตาม action/ช่วงวันที่ได้
- Settings ปรับได้จากหน้าเว็บ: max_items_per_request (5), max_active_requests_per_student (2), max_loan_days_durable (7), max_renew_count (1), max_renew_days (7), due_soon_notify_days_before (2), low_stock_threshold_default
- Dashboard: รออนุมัติ / เกินกำหนด / สต็อกต่ำ / ของที่ถูกยืมออกไปจริง (นับจาก borrow_item ไม่ใช่ผลต่างสต็อก)

3. ระบบอัตโนมัติ

- APScheduler รันเที่ยงคืน (โซนเวลาไทย): แจ้งใกล้ครบกำหนด + แจ้งเกินกำหนด (in-app + อีเมล)
- อีเมลอัตโนมัติตอนอนุมัติ/ปฏิเสธ/รับคืน + digest ถึงแอดมินเมื่อมีคำขอใหม่ (ปิดได้ด้วย ENABLE_EMAIL)
- กระดิ่งแจ้งเตือน poll 10 วิ + เสียงเตือนเฉพาะแอดมิน

---

4. กฎที่ระบบบังคับจริงในฝั่ง backend

- นักศึกษากดคืนเองไม่ได้ — ทั้ง return, renew-approve เป็น require_admin()
- คืนเข้าสต็อกเฉพาะ ok / returned_full เท่านั้น; ชำรุด/สูญหาย/ทิ้ง ต้องมีรูป
- จำนวนเป็น Integer เสมอ (ของตัดแบ่งได้ให้ตั้งหน่วยเล็กสุดแทน)
- CHECK ระดับ DB กันสต็อกติดลบ + row lock กัน race (มีเทส test_stock_race, test_equipment_group_race)
- เลขคำขอ REQ-ปี-รหัสนศ.-hex6 จาก uuid ไม่ใช่ count+1
- audit log ลบไม่ได้ (ON DELETE SET NULL + snapshot ผู้ทำ)

5. สถานะตอนนี้

Deploy จริงบน Proxmox VM (Docker Compose: postgres + backend + nginx) แล้ว — โค้ด backend/frontend ~99% ตามขอบเขต ตอนนี้อยู่ช่วง QA จากผู้ใช้จริง

ค้างอยู่ 3 เรื่อง:
1. งานวันที่ 2–3 ก.ย. (เบอร์โทร/PDPA, QR ปรับ IP, redirect หลังล็อกอิน, own-only filter) ยัง uncommitted — 22 ไฟล์
2. FRONTEND_URL ใน backend/.env ค้าง IP เก่า → ลิงก์ยืนยันอีเมล/รีเซ็ตรหัสผ่านเสีย
3. Out of scope ตามแผน: คิดค่าปรับอัตโนมัติ, LINE OA, SSO, export Excel
